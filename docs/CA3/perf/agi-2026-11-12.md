# AGI capture: Mino 0.9.0-dev on the heaviest section

Captured 25 Nov 2026 (lab dated 23 Nov). Android GPU Inspector 2025-3.3.3, System Profile, 5 s, Development Build, Galaxy S24 Ultra (Adreno 750), Android 17, tier High (URP-High: 4x MSAA, render scale 1.0, shadows, bloom), Balanced mode (~57 fps during capture). File: `agi-system-profile.perfetto`.

| Question | Answer | Evidence |
|----------|--------|----------|
| Draw calls | **33 SetPass calls, 26.2k triangles, 49.8k vertices** (Draw Calls reads 0: the SRP Batcher counts them as SetPass; dynamic batching merged 2 calls; static batching 0 because the SRP Batcher handles the static scenery). AGI System Profile has no draw-call view, so this is the lab's Unity Profiler fallback (Editor). Week 3 greybox: 23-25 SetPass, 6.1k triangles. The art pass added ~8-10 SetPass (scenery, particles, shadow pass) and ~4x triangles (about 400 scenery props) | ![Profiler-render](profiler-rendering.png) |
| Render passes | **~21 per frame** (5,961 Adreno "Surface" passes over 283 frames). Most are the bloom downsample/upsample chain (Week 3 Frame Debugger: 17 of 25 events were bloom), plus shadow map, main pass and final blit | GPU Queue 0 track |
| Overdraw | **Low: maximum ~4 layers, most of the screen 0-1.** Sky 0 (opaque). One full-screen transparent layer covers everything below the horizon (likely the seabed or a water/caustics plane on a transparent material): making it opaque would remove one blended layer from ~half the screen. Bubbles and hit/pickup particles 2 layers, ~4 where bursts overlap, small areas only. Not the bottleneck: GPU cost is the ~21 render passes and 4x MSAA. URP Rendering Debugger, Overdraw Mode Transparent, Editor Play Mode (AGI System Profile has no overdraw view) | overdraw.png |
| CPU or GPU bound | **Neither at 60 fps.** GPU busy 67.5% = **~11.8 ms per frame** of the 16.7 ms budget; CPU main-thread work ~5.8 ms (Week 9 Profiler). At 120 fps (8.3 ms budget) the GPU would be the limit at full resolution; High FPS mode's render scale 0.8 (~64% of the pixels, ~7.6 ms) is why the Perfetto trace still held 120 fps | GPU Queue 0, Surface stage durations |

**GPU stage split (5 s):** Surface 3,349 ms; Render 1,964 ms; GMEM Store Color 438 ms; GMEM Load Depth/Stencil 310 ms; GMEM Load Color 130 ms; GMEM Store Depth/Stencil 35 ms; Blit 15 ms. GMEM load/store events are 59% of the stage events: with 4x MSAA at 1080 x 2340 and ~21 passes, the tiled GPU spends much of each frame moving tiles to and from memory.

**Bottleneck named for Lab B:** GPU cost on the High tier, ~11.8 ms/frame from ~21 render passes (mostly bloom) with 4x MSAA. Fix to test: MSAA 4x -> 2x and fewer bloom iterations on URP-High; target GPU time under 8 ms and render targets under the 64 MB budget (measured 113.9 MB).
